# 要件定義

## 概要

英単語のリストをテキストとして入力すると、各単語について

1. 英単語（入力そのまま、正規化済み）
2. 日本語訳
3. その単語を含む英語の例文

の3列からなるCSVファイルを生成し、ダウンロードできるWebアプリケーション。

対象ユーザーは英語学習者（自分で単語帳を作りたい人）を想定するが、本プロジェクト自体はポートフォリオとしての公開を第一目的とする。

## 入力

- テキストエリアに英単語を改行またはカンマ区切りで入力する（例: `run\ngive up, listen`）。
- 単語だけでなく `give up` のような短いフレーズも入力として許容する。
- 入力の解析（分割・trim・空要素除去）はフロントエンドではなくバックエンドで行う。詳細は [docs/api.md](./api.md) を参照。
- 1リクエストあたりの上限（単語数・文字数）を設ける。具体的な数値は [docs/api.md](./api.md) に記載。

## 出力

- CSVファイル（UTF-8 BOM付き、ヘッダ `word,translation,example_sentence`）としてダウンロードできる。
- ダウンロード前にブラウザ上で結果をプレビュー表示する（テーブル形式）。
- 詳細な列仕様・エンコーディング・命名規則は [docs/api.md](./api.md) を参照。

## MVPスコープの確定事項

以下はユーザーとの確認の上で確定した仕様。実装時に迷わないよう明記する。

| 項目 | 決定事項 | 理由・補足 |
|---|---|---|
| 例文の数 | 1単語につき1例文のみ | シンプルさを優先。複数例文の提供はV2候補 |
| 見つからない場合の扱い | 該当セル（訳語 or 例文）のみ空欄にし、行自体は削除しない | ユーザーがどの単語がヒットしなかったかを一覧で把握できるようにするため |
| 単語のマッチング | 完全な語形一致のみ（大文字小文字は無視）。ステミング・見出し語化（lemmatization）は行わない | MVPの実装コストを抑えるため。例えば `running` を入力しても辞書・例文コーパス側に `run` の形でしか存在しない場合はヒットしない |
| フレーズ入力 | EJDictに同一表記のフレーズ見出し語があれば辞書訳はヒットする。例文は「そのフレーズが単語境界で一致する文」がコーパス中にあればヒットする | 詳細は [docs/data-pipeline.md](./data-pipeline.md) |
| 例文データセット | Tatoeba (`eng_sentences.tsv`) を採用 | 選定理由は [docs/datasets.md](./datasets.md) |
| 辞書データセット | EJDict (CC0) を採用 | 選定理由は [docs/datasets.md](./datasets.md) |

## 既知の制約

- **辞書カバレッジの限界**: EJDictの実際の収録数は約47,000見出し語であり、巷で言われる「20万件規模」という情報は誤り（本プロジェクトの調査で実測確認済み、詳細は [docs/datasets.md](./datasets.md)）。専門用語・固有名詞・比較的新しい語などは訳語が見つからない可能性が高い。
- **例文コーパスの性質**: Tatoebaはユーザー投稿による文集であり、文の難易度・自然さにはばらつきがある。極端に短い/長い文は選定アルゴリズムでフィルタする（[docs/data-pipeline.md](./data-pipeline.md) 参照）が、完全な品質保証はしない。
- **語形一致のみ**: 活用形・複数形などの揺れは吸収しない（V2で改善検討）。

## V2以降の検討事項（本タスクのスコープ外、参考記録）

- ステミング/見出し語化による柔軟なマッチング
- 1単語あたり複数例文・ユーザーが件数を指定できるUI
- 例文の日本語訳もあわせて表示（Tatoebaの `links.csv` を用いた対訳ペアの活用）
- EJDict以外の辞書データソースを追加してカバレッジを補強
- 認証・利用履歴の保存
